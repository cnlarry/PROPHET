# Crypto Signal Agent (CSA) 项目规划文档

**项目代号**：CSA  
**项目目标**：构建一套 24 小时加密货币情报/情绪/链上/交易所数据监控系统，提取结构化、可被量化交易策略直接消费的交易信号，并逐步实现与现有量化系统的无缝集成。  
**核心价值**：在纯技术指标之外，引入“情报/情绪/异常事件”维度，提升策略在极端行情下的提前反应能力和胜率。  
**当前日期**：2025年12月30日  
**预期总周期**：4–16 周（视个人投入时间、已有代码基础和信号验证效果而定）

## 1. 项目愿景与边界

### 愿景
- 成为个人量化交易的“第二大脑”：人类只做最终决策，系统完成 90%+ 的信息收集、过滤、交叉验证与初步判断
- 输出格式对量化友好：结构化 JSON，便于 merge 到 Pandas、直接喂模型或触发 webhook
- 可解释性优先：每条信号必须附带可追溯的证据链（链接、截图、原始数据）

### 非目标（当前版本不做）
- 全自动下单执行（可留扩展接口，但不包含风控、仓位管理）
- 覆盖全部小币 / meme 币（初期聚焦 BTC、ETH、SOL 等高流动性资产）
- 复杂的情绪细粒度多语言分析（中文/英文为主）
- 商用级高可用、分布式部署

## 2. 阶段拆分与里程碑

| 阶段 | 预计耗时 | 核心交付物 | 验收标准 | 建议优先级 |
|------|----------|------------|----------|------------|
| 0    | 1–3 天   | 零代码快速验证通道 | 每天至少推送 3–10 条信号到 Telegram/Discord | ★★★★★ |
| 1    | 1–3 周   | MVP Dashboard（可视化 + 人工 Review） | 可在浏览器查看最新信号 + 手动打标签 | ★★★★☆ |
| 2    | 2–5 周   | 量化系统集成（数据库/Webhook） | 信号可被主策略程序读取并参与回测 | ★★★★★ |
| 3    | 3–8 周   | 闭环反馈 + 偏好学习 | 系统逐步减少垃圾信号，接近用户真实偏好 | ★★★★☆ |
| 4    | 长期     | 生产稳定 + 多资产扩展 | 运行 30 天无重大中断，覆盖 ≥3 个主流币种 | ★★★☆☆ |

## 3. 阶段 0 – 快速验证（强烈建议第一个做）

**目标**：用最少投入验证“情报信号”对现有策略是否有增益  
**时间**：1–3 天  
**成本**：≈0 元（利用免费额度）

### 核心功能清单
- 监控 3–5 类高优先级信号（建议从以下选择或自定）
  - 极端资金费率（>0.1% 或 <-0.05% 持续）
  - 大规模爆仓（1h 内 >1 亿美金）
  - 链上巨鲸异动（单笔 ≥500 BTC 或等值）
  - 监管/ETF/宏观突发（美联储、SEC、特朗普相关等）
  - KOL/聪明钱集群喊单（同一时间多账号同方向发声）
- 推送格式：Telegram/Discord 消息或 Google Sheet 行
- 每条信号包含：时间、币种、方向建议、置信度、证据链接、简短理由

### 推荐实现组合（选 1–2 种快速跑通）
1. Grok 多标签页哨兵（最快）
2. Gemini Gems + n8n 自动化
3. ChatGPT Custom GPT + Google Apps Script 写 Sheet
4. Claude Projects（如果已有 Pro 账号）

### 阶段 0 退出条件
- 连续运行 7–14 天
- 累计产生 ≥30 条信号
- 人工判断其中 ≥20% 有潜在交易价值（提前于纯技术指标）

## 4. 阶段 1 – MVP Dashboard（橙子风格参考版）

**目标**：拥有可交互的统一界面，方便 Review、打标签、导出  
**时间**：1–3 周  
**技术栈建议**（2025 年底性价比最高组合）

| 部分     | 推荐工具                     | 备选工具                     | 理由                              |
|----------|------------------------------|------------------------------|-----------------------------------|
| 后端逻辑 | Cursor + Python + FastAPI    | Replit Agent / Windsurf      | AI 辅助编码效率最高               |
| 数据库   | SQLite（初期）→ PostgreSQL   | Supabase / PlanetScale       | 轻量 → 可扩展                     |
| 前端     | Google AI Studio / v0.dev    | Lovable.dev / Bolt.new       | 零基础最快出好看界面              |
| 大模型   | Grok（X实时）+ Gemini Flash + Claude 3.5 | OpenAI o1-mini（逻辑） | 性价比 + 能力互补                 |
| 调度     | n8n / Cron + Docker          | Railway / Fly.io             | 免费额度 + 易部署                 |

### 核心模块清单（建议按此顺序开发）

1. 数据采集层（最重要）
   - RSS 订阅（CoinDesk、The Block、Wu Blockchain 等）
   - X 关键词/语义监控（Grok API 或间接方式）
   - 交易所 WebSocket（Binance 资金费率、OI、爆仓）
   - 链上免费 API（Arkham、Glassnode 免费部分、Whale Alert）

2. 清洗 & 去重层
   - 文本相似度（Gemini embedding 或 sentence-transformers）
   - 时间窗口合并（同一事件 30 分钟内合并）

3. 信号打分模型（可简单起步，后续迭代）
   - 时效性（30%）：距离现在越近越高
   - 相关性（40%）：与白名单关键词匹配度
   - 异常强度（20%）：偏离均值多少个标准差
   - 历史一致性（10%）：该类信号过去触发效果

4. 输出 & Review 层
   - JSON 结构（必备字段）
     ```json
     {
       "id": "uuid",
       "timestamp": "2025-12-30T14:35:22Z",
       "symbol": "BTCUSDT",
       "direction": "long/short/neutral",
       "confidence": 0.72,
       "category": "funding_rate_extreme",
       "reason": "一句话核心逻辑",
       "evidence": ["链接1", "链接2"],
       "raw_data": {...}
     }
     ```
   - Review 动作：批准 / 忽略 / 已交易 / 错误标签（用于后续学习）

## 5. 阶段 2 – 量化系统集成

**集成方式选择**（建议优先级顺序）

1. **数据库共享**（推荐）
   - 同实例 SQLite / PostgreSQL
   - 量化代码直接读表

2. **HTTP 接口**
   - FastAPI 暴露 `/signals?since=...`
   - 或 Webhook 推送新信号

3. **文件/消息队列**
   - 定时写 CSV / JSON Lines
   - 通过 Redis / Kafka（后期）

**回测价值评估方法**
- 收集至少 30–60 天历史信号（可先手动标注）
- 对比：原策略 vs 原策略 + 信号过滤/加权
- 关键指标：夏普比率提升、最大回撤降低、胜率变化

## 6. 常见风险 & 应对措施

| 风险                     | 概率 | 影响 | 应对措施                              |
|--------------------------|------|------|---------------------------------------|
| 垃圾信息淹没有效信号     | 高   | 高   | 白名单 + 多轮过滤 + 反馈学习          |
| 大模型幻觉/误判          | 中   | 高   | 强制附证据 + 多模型交叉验证           |
| API 限额/费用超支        | 中   | 中   | 优先免费额度 → 降频 → 缓存           |
| 系统不稳定/数据丢失      | 低   | 高   | SQLite 每日备份 + 简单日志            |
| 信号延迟过大             | 中   | 中   | 优先短周期数据源（WS > RSS > LLM轮询）|

## 7. 后续可能扩展方向（按价值排序）

1. 更多数据源（Dune、Nansen、Santiment、NewsAPI）
2. 信号 → 仓位大小建议（基于历史胜率）
3. 情绪时间序列特征（喂给 LSTM/Transformer）
4. 多币种相关性分析（当 BTC 恐慌时 SOL 是否跟随）
5. 半自动/自动交易接口（需严格风控）
