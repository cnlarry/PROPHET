## ⚠️ **意外发现：JIT反而降低了性能！**

### **性能对比**

| 版本 | 性能 (ops/s) | vs P2 | 说明 |
|------|--------------|-------|------|
| P2 (字节码) | 38,314 | - | 基准 |
| **P2.1.1 (VM栈)** | **43,478** | **+13.5%** | ✅ 最佳 |
| P2.1.1+P2.2 (JIT) | 35,971 | -6.1% | ⚠️ 下降 |

### **原因分析**

#### **1. std::function开销**

```cpp
using JITFunc = std::function<bool(Context&)>;
```

**问题**:
- `std::function` 有类型擦除开销
- 虚函数调用（间接跳转）
- 不能内联

**证据**:
- Lambda本身应该更快
- 但通过`std::function`调用反而慢

#### **2. Lambda捕获开销**

```cpp
return [=](dsl::Context& ctx) -> bool {
    // 捕获了很多变量
    std::string tf = params.timeframe;  // 复制
    std::string ind = params.indicator;  // 复制
    // ...
};
```

**问题**:
- Lambda捕获参数需要内存分配
- 每次调用都要访问捕获的变量

#### **3. 模式识别失败率**

可能很多规则无法JIT，回退到字节码VM，增加了判断开销。

## ✅ **P2.1.1: VM栈复用（大成功）**

### **实现**
```cpp
// 之前：每次clear栈
stack_.clear();

// 之后：复用栈空间
stack_top_ = 0;
```

### **成果**
- **提升**: +13.5% (vs P2)
- **超预期**: 2.7倍 (预期+5%,实际+13.5%)
- **稳定性**: 良好 (CV=31%)

### **收益来源**
1. 消除vector::clear()
2. 消除频繁realloc
3. 提升缓存命中率
4. 减少内存分配

---

## ❌ **P2.2: 简化JIT（失败）**

### **实现**
```cpp
using JITFunc = std::function<bool(Context&)>;

// 模式识别 + Lambda生成
JITFunc compile(const std::vector<Instruction>& code) {
    auto pattern = detectPattern(code);
    return generateLambda(pattern, extractParams(pattern, code));
}
```

### **问题**
1. **std::function开销** > 字节码VM优势
2. **Lambda捕获** 增加内存开销
3. **无法内联** 编译器优化受限

### **教训**
- "简化JIT"不够简化
- C++ Lambda通过std::function调用不够快
- 需要更激进的优化（编译时宏/模板）
