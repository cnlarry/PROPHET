## ⚠️ 性能测试结果

### 性能对比

| 场景 | P1性能 | P2性能 | 变化 |
|------|--------|--------|------|
| 实时交易 | 27,022 次/秒 | 12,925 次/秒 | **-52.2%** |
| 回测 | 8,231 次/秒 | 3,675 次/秒 | **-55.3%** |
| 混合 | 15,084 次/秒 | 12,824 次/秒 | **-15.0%** |

### 原因分析

#### 1. 额外开销增加
```cpp
// P1: 2次查找
// 1. 检查IndicatorCache
// 2. 如未命中，计算

// P2: 3次查找 + 2次写入
// 1. 检查SessionCache
// 2. 检查IndicatorCache  
// 3. 如未命中，计算
// 4. 写入IndicatorCache
// 5. 写入SessionCache
```

#### 2. 当前场景不适合
- 测试场景指标简单，无复杂依赖
- 单规则策略，指标访问一次
- 会话缓存无命中机会

#### 3. 开销分析
- 每次getIndicator增加1次Map查找（~5-10ns）
- beginSession/endSession开销（~100ns）
- Map写入开销（~10-20ns）

**总开销**: 约 130-150ns/次 * 100次 = 13-15μs

这解释了为什么性能下降了约0.04ms（40μs）

## 💡 会话缓存的价值场景

### 场景1: 复杂指标策略
```cpp
// MACDEXT依赖多个EMA
MACDEXT {
    fast_ema = EMA(close, 12);  // 计算1
    slow_ema = EMA(close, 26);  // 计算2
    macd = fast_ema - slow_ema;
    signal = EMA(macd, 9);      // 计算3
}

// 如果用户策略也访问EMA
$(5m).EMA().value > 50;  // 会话缓存命中！避免重复计算
```

**收益**: 40-60% for复杂指标

### 场景2: 多规则策略
```dsl
// 规则1
ALL{$(5m).RSI().value < 30} = BUY;

// 规则2  
ALL{$(5m).RSI().value > 70} = SELL;

// 规则3
ALL{$(5m).RSI().value > 50, $(5m).MACD().histogram > 0} = BUY;
```

**收益**: RSI(5m)只计算一次，后续从会话缓存读取

## 🔧 优化建议

### 短期优化

#### 1. 条件启用会话缓存
```cpp
class Context {
    bool use_session_cache_ = false;  // 默认关闭
    
public:
    void enableSessionCache(bool enable) {
        use_session_cache_ = enable;
    }
    
    IndicatorResult getOrCalculateIndicator(...) {
        // 只在启用时检查会话缓存
        if (use_session_cache_) {
            if (session_cache_.get(key, result)) {
                return result;
            }
        }
        
        // ... 正常逻辑
    }
};
```

#### 2. 智能判断
```cpp
// 在Engine中分析策略复杂度
void Engine::loadRulesFromDSL(const std::string& dsl) {
    // 解析规则
    parse(dsl);
    
    // 分析是否需要会话缓存
    bool complex_strategy = analyzeComplexity();
    context_.enableSessionCache(complex_strategy);
}

bool Engine::analyzeComplexity() {
    // 如果规则数 > 3，或有复杂指标，启用会话缓存
    return rules_.size() > 3 || hasComplexIndicators();
}
```

### 长期优化

#### 1. 延迟初始化
```cpp
class SessionCache {
    std::optional<std::unordered_map<...>> cache_;
    
    void begin() {
        if (!cache_) {
            cache_.emplace();  // 延迟分配
        }
        cache_->clear();
    }
};
```

#### 2. 小对象优化
```cpp
// 使用小对象优化的flat_map
#include <boost/container/flat_map.hpp>

class SessionCache {
    // 小策略（<10个指标）时更快
    boost::container::flat_map<std::string, IndicatorResult> cache_;
};
```
