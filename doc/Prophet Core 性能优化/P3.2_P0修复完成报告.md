## 关键发现

### 发现1：批次大小临界点

**临界批次 = 32策略**

小于32策略时：
```
线程创建开销 > 并行计算收益
→ 并行反而更慢
```

大于等于32策略时：
```
并行计算收益 > 线程创建开销
→ 并行开始有效
```

### 发现2：加速比瓶颈

**理论加速比**：16x (16核CPU)  
**实际加速比**：2.03x (64策略)  
**效率**：12.7% (2.03/16)

**瓶颈原因**：
1. `std::async`每次创建线程（~10-50μs/线程）
2. 64策略 × 50轮 × 64线程 = 204,800次线程创建
3. 线程开销：204,800 × 30μs ≈ 6秒
4. 实际测试时间：50轮 × 976μs ≈ 0.05秒
5. **线程开销是计算时间的120倍！**

### 发现3：Python绑定层开销

对比64策略：
- Python串行：32,326 ops/s
- Batch串行：23,223 ops/s（更慢28%）

**原因分析**：
- C++函数调用开销
- Signal对象创建/转换
- 向量返回的拷贝

## 下一步行动

### 立即执行（P1）

**1. 实现线程池**

```cpp
class BatchEngine {
private:
    struct ThreadPool {
        std::vector<std::thread> threads_;
        std::queue<std::function<void()>> tasks_;
        std::mutex mutex_;
        std::condition_variable cv_;
        bool stop_ = false;
        
        void worker() {
            while (true) {
                std::function<void()> task;
                {
                    std::unique_lock<std::mutex> lock(mutex_);
                    cv_.wait(lock, [this] { 
                        return stop_ || !tasks_.empty(); 
                    });
                    
                    if (stop_ && tasks_.empty()) return;
                    
                    task = std::move(tasks_.front());
                    tasks_.pop();
                }
                task();
            }
        }
    };
    
    std::unique_ptr<ThreadPool> thread_pool_;
};
```
