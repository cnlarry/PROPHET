## 🎯 建议2：修复P2性能问题（优先级：🔴 高）

### 2.1 问题诊断：为什么SessionCache慢？

**关键问题**：
1. **开销1**: `beginSession()` / `endSession()` 每次调用都clear整个map
2. **开销2**: `thread_local` 变量初始化和访问开销
3. **开销3**: 字符串key生成和hash计算
4. **收益低**: 简单策略缓存命中率不高（<30%）

**测试数据**（推测）：
```cpp
// 每次 get_signal() 调用
context_.beginSession();      // ~5-10μs (map clear)
  // ... 策略评估 ...
  session_cache_.get(key);    // ~2-3μs (hash + lookup)
  session_cache_.set(key);    // ~3-5μs (hash + insert)
context_.endSession();        // ~5-10μs (map clear)

// 总开销：15-28μs
// P1单次耗时：37μs
// 额外开销比例：40-75% ❌
```

---

### 2.2 解决方案A：完全移除SessionCache（推荐）

**适用场景**: 如果缓存命中率 < 40%

**步骤**：
1. 在`Context`中添加开关：`disable_session_cache_`
2. 在`getSignal()`中跳过`beginSession()`/`endSession()`
3. 运行性能测试对比

**预期效果**: 恢复到P1的27k ops/s水平 ✅

**实施时间**: 1小时

### 2.3 解决方案B：优化SessionCache（备选）

**适用场景**: 如果缓存命中率 > 50%

**优化策略**：

#### B1. 无锁设计
```cpp
// 替换 thread_local map 为固定大小数组
constexpr size_t CACHE_SIZE = 32;
struct CacheEntry {
    uint64_t key_hash;
    IndicatorResult value;
    bool valid;
};
static thread_local std::array<CacheEntry, CACHE_SIZE> cache_;
```

**优点**: 
- 无动态内存分配
- 查找O(1)（直接数组索引）
- beginSession()只需标记valid=false

**预期提升**: +5-10% (恢复部分性能)

---

#### B2. 智能缓存策略
```cpp
// 只缓存"昂贵"的指标计算
bool should_cache(const std::string& indicator_name) {
    // MACD/RSI/EMA等复杂指标才缓存
    return expensive_indicators_.count(indicator_name) > 0;
}
```

**预期提升**: +3-5%

### 3.2 实现方案

#### 创建标准化benchmark

**文件**: `examples/benchmarks/performance_regression_test.py`

```python
"""
Prophet Core 性能回归测试
标准化测试环境，确保结果可重复
"""

import sys
import os
import time
import numpy as np
from Prophet import Core

# 固定随机种子
np.random.seed(42)

# 标准测试配置
KLINE_SIZES = [100, 500, 1000]
ITERATIONS = 5000
WARMUP_ITERATIONS = 100

def benchmark_strategy(strategy_dsl, klines, name):
    """标准化benchmark函数"""
    engine = Core.Engine()
    engine.load_strategy(strategy_dsl)
    engine.SetKlines(*klines)
    
    # 预热
    for _ in range(WARMUP_ITERATIONS):
        engine.get_signal(100.0, 1000000)
    
    # 测试（多次取平均）
    results = []
    for run in range(5):
        start = time.perf_counter()
        for _ in range(ITERATIONS):
            engine.get_signal(100.0, 1000000)
        elapsed = time.perf_counter() - start
        results.append(ITERATIONS / elapsed)
    
    avg_speed = np.mean(results)
    std_speed = np.std(results)
    
    return {
        'name': name,
        'avg_speed': avg_speed,
        'std_speed': std_speed,
        'coefficient_of_variation': std_speed / avg_speed
    }

# 性能基准
PERFORMANCE_BASELINES = {
    'P1': 27041,
    'P2': 20764,
    'P3': 24020,
}

def check_regression(current_speed, baseline_name='P3'):
    """检查性能回归"""
    baseline = PERFORMANCE_BASELINES[baseline_name]
    change_pct = (current_speed / baseline - 1) * 100
    
    if change_pct < -5.0:
        print(f"❌ 性能回归！相比{baseline_name}下降{-change_pct:.1f}%")
        return False
    elif change_pct > 5.0:
        print(f"✅ 性能提升！相比{baseline_name}提升{change_pct:.1f}%")
        return True
    else:
        print(f"✅ 性能稳定，相比{baseline_name}变化{change_pct:+.1f}%")
        return True
```

### 4.2 P3.3：多线程并行评估

**动机**: 充分利用多核CPU

**优化思路**：
```cpp
// 并行评估N个策略
#include <thread>
#include <future>

std::vector<Signal> evaluateParallel(
    const std::vector<std::string>& strategies
) {
    std::vector<std::future<Signal>> futures;
    
    for (const auto& strategy : strategies) {
        futures.push_back(
            std::async(std::launch::async, [&]() {
                // 每个线程独立的Context
                thread_local Context ctx;
                return ctx.evaluate(strategy);
            })
        );
    }
    
    // 收集结果
    std::vector<Signal> results;
    for (auto& f : futures) {
        results.push_back(f.get());
    }
    return results;
}
```

**预期提升**: 2-4倍（取决于核心数）

**实施成本**: 高（3-5天）

**注意**: 需确保`Context`的线程安全（P1已完成）
