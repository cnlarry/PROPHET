# Prophet Core SessionCache移除测试报告

**日期**: 2025-11-01  
**测试目标**: 通过禁用SessionCache恢复P1性能水平（27k ops/s）  
**测试结果**: ❌ 失败 - 性能未恢复，且发现测试环境严重不稳定

---

## 📊 测试结果总结

### 禁用SessionCache前后对比

| 版本 | 快速测试 | 精确测试 | 可靠测试(中位数) | 波动 |
|------|----------|----------|-----------------|------|
| **SessionCache启用** | 24,020 ops/s | 20,922 ops/s | - | - |
| **SessionCache禁用** | 24,521 ops/s | 19,178 ops/s | **17,678 ops/s** | 244.7% |

**结论**: 
- ✅ SessionCache禁用后略有提升（+2-5%）
- ❌ 但远未达到P1的27k ops/s水平
- ❌ 性能波动巨大，测试环境不可信

---

## 🔍 根本原因分析

### 1. 测试环境问题（主要）

#### CPU频率波动

```
测试序列分析（10次运行）：
Run 1:   5,835 ops/s  ← CPU冷启动，低频率
Run 2:  11,236 ops/s  ← 开始升频
Run 3:  15,275 ops/s  ← 继续升频
Run 4:  18,352 ops/s  ← 接近稳定
Run 5:  16,148 ops/s  ← 略有波动
Run 6:  18,154 ops/s  ↓
Run 7:  18,768 ops/s  ↓ 稳定在18-20k
Run 8:  17,202 ops/s  ↓
Run 9:  19,107 ops/s  ↓
Run 10: 20,113 ops/s  ← 最高

波动范围: 5.8k - 20.1k (3.4倍差异) ❌
```

**原因**：
- Windows笔记本电源管理（平衡/省电模式）
- CPU从低功耗状态逐渐提升到高性能状态
- 前几次运行触发CPU升频

**证据**：
- 第1次运行性能极差（5.8k）
- 逐渐上升到稳定水平（18-20k）
- 符合Intel Turbo Boost行为特征

---

#### 缓存预热效应

```
时间序列分析：
├─ 0-1秒:   冷启动，指令缓存miss率高
├─ 1-3秒:   L1/L2缓存逐渐填充
├─ 3-5秒:   L3缓存预热
└─ >5秒:    稳定状态
```

**影响**：
- 前几次运行受缓存miss影响严重
- 后续运行缓存命中率提升

### 3. SessionCache的实际开销（结论）

#### 对比分析

```
SessionCache启用（稳定后）:  ~20k ops/s
```

**结论**：

## 💡 深入分析：为什么无法恢复到P1？

### 假设1：P1性能是在更好的硬件/环境下测得

**支持证据**：
- 当前稳定性能18-20k ops/s
- P1声称27k ops/s
- 差距7-9k ops/s (35-45%)

**可能场景**：
- P1测试在台式机（更高CPU频率，更好散热）
- 当前测试在笔记本（功耗限制，散热限制）

---

### 假设2：P1到P2/P3有其他性能损失

**可能原因**：
- P1 → P2: SessionCache引入（已测试，影响小）
- P1 → P2: Context重构引入额外开销？
- P1 → P3: SIMD集成引入分支判断开销？

**需要验证**：
- 回滚到P1代码，重新测试
- 对比P1和P3的代码差异
- 使用profiler定位瓶颈

---

### 假设3：测试方法差异

**P1测试方法（推测）**：
```python
# 可能更简单的测试
for _ in range(1000):
    signal = engine.get_signal(price, time)
```

**当前测试方法**：
```python
# 更复杂，包含创建/销毁
for run in range(10):
    engine = Core.Engine()
    # ... 测试 ...
    del engine
    gc.collect()
```

**差异**：
- 每次run都创建新engine（开销）
- 更多的GC触发
- 更多的内存分配/释放

## 🔧 技术细节：SessionCache禁用实现

### 代码修改

```cpp
// Prophet.Core/src/strategy/engine.cpp (line 296-298)

// 原代码：
bool enable_session_cache = analyzeStrategyComplexity();

// 修改后：
bool enable_session_cache = false;  // 强制禁用
```

### 效果

- `Context::beginSession()` 快速返回（if check）
- `Context::endSession()` 快速返回（if check）
- `SessionCache::get/set` 不再被调用

### 开销分析

```cpp
void Context::beginSession() {
    if (!session_cache_enabled_) {
        return;  // ~1纳秒（单个分支预测）
    }
    session_cache_.begin();  // ~5-10μs（map清空）
}
```

**理论节省**：每次get_signal()节省10-20μs  
**实际节省**：1-2μs（因为快速路径已优化）
