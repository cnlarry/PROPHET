## 📋 优化内容

### 🔥 优先级P0: 指标计算会话缓存

#### 问题分析

**当前问题**: 复杂指标重复计算依赖指标

```cpp
// 示例：计算MACDEXT
IndicatorResult calculate_MACDEXT(...) {
    // 每次都重新计算EMA
    auto fast_ema = calculate_EMA(klines, 12);  // 计算1
    auto slow_ema = calculate_EMA(klines, 26);  // 计算2
    
    // 如果用户也访问EMA
    context.getIndicator("EMA", "5m");  // 计算3（重复！）
}
```

**解决方案**: 在单次evaluate会话中缓存中间结果

```cpp
// 会话缓存
Signal Engine::evaluate() {
    calculator_.beginSession();  // 开始会话
    
    // EMA只会计算一次，后续都从缓存读取
    auto macd = context.getIndicator("MACDEXT", "5m");
    auto ema = context.getIndicator("EMA", "5m");
    
    calculator_.endSession();  // 结束会话，清空缓存
    return signal;
}
```

**步骤2**: 更新Calculator集成会话缓存

```cpp
class Calculator {
private:
    SessionCache session_cache_;
    
public:
    void beginSession() {
        session_cache_.begin();
    }
    
    void endSession() {
        session_cache_.end();
    }
    
    IndicatorResult calculate(const std::string& indicator,
                              const std::vector<Kline>& klines,
                              const IndicatorParams& params) {
        // 生成会话缓存键
        std::string key = indicator + ":" + params.hash();
        
        // 检查会话缓存
        IndicatorResult result;
        if (session_cache_.get(key, result)) {
            return result;  // 会话缓存命中
        }
        
        // 计算并缓存
        result = calculate_internal(indicator, klines, params);
        session_cache_.set(key, result);
        
        return result;
    }
};
```

```cpp
    // 结束会话：清空会话缓存
```

### ⚡ 优先级P1: AST字节码编译

#### 问题分析

**当前问题**: AST树遍历开销大

```cpp
// 当前：每次evaluate都要遍历AST树
Value Evaluator::evaluate(const ASTNode* node) {
    switch (node->type) {  // 虚函数调用
        case BinaryOp:
            auto left = evaluate(node->left);   // 递归
            auto right = evaluate(node->right); // 递归
            return compute(op, left, right);
    }
}
```

**解决方案**: 编译为字节码，顺序执行

```cpp
// 字节码执行：无递归，无虚函数
Value VM::execute(const std::vector<Instruction>& code) {
    std::vector<Value> stack;
    
    for (const auto& inst : code) {
        switch (inst.opcode) {
            case LOAD_CONST:
                stack.push_back(inst.operand);
                break;
            case ADD:
                auto b = stack.pop();
                auto a = stack.pop();
                stack.push(a + b);
                break;
        }
    }
    
    return stack.back();
}
```

#### 实施步骤

**步骤1**: 设计字节码指令集

```cpp
// include/prophet/bytecode/opcodes.hpp
enum class Opcode : uint8_t {
    // 数据加载
    LOAD_CONST,           // 加载常量
    LOAD_INDICATOR,       // 加载指标字段
    LOAD_ENV,             // 加载环境变量
    
    // 算术运算
    ADD, SUB, MUL, DIV, MOD,
    NEG,                  // 取负
    
    // 比较运算
    EQ, NE, GT, LT, GE, LE,
    
    // 逻辑运算
    AND, OR, NOT,
    
    // 聚合函数
    ALL, ANY, NONE,
    
    // 控制流
    JUMP,                 // 无条件跳转
    JUMP_IF_FALSE,        // 条件跳转
    
    // 其他
    RETURN,               // 返回
    POP,                  // 弹出栈顶
};

struct Instruction {
    Opcode opcode;
    Value operand;        // 操作数（如常量、变量名）
    int jump_offset;      // 跳转偏移（用于JUMP指令）
};
```

**步骤4**: 集成到Engine

```cpp
class Engine {
private:
    std::vector<CompiledRule> compiled_rules_;
    
public:
    void loadRulesFromDSL(const std::string& dsl) {
        // 解析DSL -> AST
        auto ast = parser_.parse(dsl);
        
        // 编译AST -> 字节码
        BytecodeCompiler compiler;
        for (const auto& rule : ast.rules) {
            auto bytecode = compiler.compile(rule);
            compiled_rules_.push_back({bytecode, rule.action});
        }
    }
    
    Signal evaluate() {
        BytecodeVM vm;
        
        for (const auto& rule : compiled_rules_) {
            // 执行字节码
            auto result = vm.execute(rule.bytecode, context_);
            
            if (result.toBool()) {
                return Signal{rule.action, 1.0};
            }
        }
        
        return Signal{"HOLD", 0.0};
    }
};
```

## 💡 技术亮点

- ✅ **零配置**: 自动生效，无需用户干预
- ✅ **智能管理**: 会话结束自动清理
- ✅ **显著收益**: 复杂指标性能提升60%+

- ✅ **性能**: 无递归、无虚函数调用

- ✅ **可缓存**: 编译一次，重复使用

- 字节码减少评估开销
- 会话缓存减少指标计算开销
- 总体性能提升 > 单项之和

## ⚠️ 风险与挑战

### 会话缓存风险

1. **内存占用**: 会话缓存可能占用较多内存
   - **缓解**: 设置缓存大小上限
   - **缓解**: 会话结束立即清理

2. **缓存失效**: 参数变化时缓存可能失效
   - **缓解**: 缓存键包含参数哈希

### 字节码编译风险

1. **实现复杂度**: 编译器和VM实现较复杂
   - **缓解**: 分阶段实施，先简单后复杂
   - **缓解**: 充分测试

2. **调试困难**: 字节码难以调试
   - **缓解**: 添加反汇编工具
   - **缓解**: 保留AST评估模式作为fallback

3. **兼容性**: 需要保证与现有DSL完全兼容
   - **缓解**: 完整的测试用例覆盖
