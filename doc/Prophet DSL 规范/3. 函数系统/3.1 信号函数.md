## 1. 信号函数概述

### 1.1 什么是信号函数？

信号函数（Signal Function）是 Prophet DSL 的核心构造，用于**组合多个条件表达式**并根据满足情况**生成交易信号**。

### 1.2 基本语法

```javascript
SIGNAL_FUNCTION(parameters) {
  condition1;
  condition2;
  ...
} = SIGNAL_TYPE;
```

- **SIGNAL_FUNCTION**: 信号函数名称（ALL/ANY/NONE/MIN/COUNT/MAX/VOTE/WEIGHTED）
- **parameters**: 可选参数（如阈值、数量等）
- **conditions**: 条件列表（布尔表达式）
- **SIGNAL_TYPE**: 信号类型（BUY/SELL/HOLD）

### 1.3 信号函数分类

| 分类 | 函数 | 描述 |
|------|------|------|
| **基础逻辑** | ALL, ANY, NONE | 简单的逻辑组合 |
| **数量控制** | MIN, COUNT, MAX, VOTE | 基于满足条件数量的判断 |
| **加权评分** | WEIGHTED | 为条件分配权重，进行加权评分 |

## 2. 基础信号函数

### 2.1 ALL - 全部满足

**功能**: 所有条件都必须满足时才会触发信号。

**语法**:
```javascript
ALL {
  condition1;
  condition2;
  ...
} = SIGNAL_TYPE;
```

**特点**:
- ✅ 最严格的信号条件
- ✅ 适合确定性强的策略
- ✅ 降低假信号

**示例 1: 多维度确认**
```javascript
// 趋势、动量、成交量三重确认
ALL {
  $(1h).MACD().trend = BULLISH;
  $(1h).RSI().value > 50;
  $(1h).OBV().trend = BULLISH;
} = BUY;
```

**示例 2: 多时间框架共振**
```javascript
// 所有时间框架都看涨
ALL {
  $(5m).MA().trend = BULLISH;
  $(15m).MA().trend = BULLISH;
  $(1h).MA().trend = BULLISH;
} = BUY;
```

**适用场景**:
- 🎯 高确定性策略
- 🎯 保守型交易
- 🎯 多维度验证

---

### 2.2 ANY - 任一满足

**功能**: 任意一个条件满足时就会触发信号。

**语法**:
```javascript
ANY {
  condition1;
  condition2;
  ...
} = SIGNAL_TYPE;
```

**特点**:
- ✅ 最宽松的信号条件
- ⚠️ 可能产生较多信号
- ✅ 适合多入场点策略

**示例 1: 多指标入场**
```javascript
// 任一指标超买即卖出
ANY {
  $(1h).RSI().value > 70;
  $(1h).STOCHRSI().overbought = true;
  $(1h).MFI().value > 80;
} = SELL;
```

**示例 2: 多形态识别**
```javascript
// 任一看涨形态出现
ANY {
  $(1h).MACD().crossover_type = GOLDEN_CROSS;
  $(1h).KDJ().crossover_type = GOLDEN_CROSS;
  $(1h).MA().golden_cross = true;
} = BUY;
```

**适用场景**:
- 🎯 积极型交易
- 🎯 多机会捕捉
- 🎯 止损/止盈触发

---

### 2.3 NONE - 全部不满足

**功能**: 所有条件都不满足时才会触发信号。

**语法**:
```javascript
NONE {
  condition1;
  condition2;
  ...
} = SIGNAL_TYPE;
```

**特点**:
- ✅ 反向逻辑判断
- ✅ 适合排除性条件
- ✅ 用于风险规避

**示例 1: 无风险信号时入场**
```javascript
// 无任何超买信号
NONE {
  $(1h).RSI().value > 70;
  $(1h).STOCHRSI().overbought = true;
  $(1h).MFI().value > 80;
} = BUY;
```

**示例 2: 排除不利市场状态**
```javascript
// 无不利因素时持有
NONE {
  $(1h).MACD().trend = BEARISH;
  $(1h).RSI().value < 30;
  $(1h).ADX().value < 20;
} = HOLD;
```

**适用场景**:
- 🎯 风险过滤
- 🎯 反向确认
- 🎯 市场状态排除

## 3. 数量控制信号函数

### 3.1 MIN - 至少满足

**功能**: 至少满足 N 个条件时触发信号。

**语法**:
```javascript
MIN(n) {
  condition1;
  condition2;
  ...
} = SIGNAL_TYPE;
```

**参数**:
- `n`: 至少需要满足的条件数量（整数，> 0）

**特点**:
- ✅ 提供灵活的确认度
- ✅ 平衡严格性和灵活性
- ✅ 适合多维度部分确认

**示例 1: 多维度部分确认**
```javascript
// 至少2个指标看涨
MIN(2) {
  $(1h).MACD().trend = BULLISH;
  $(1h).RSI().value > 50;
  $(1h).ADX().value > 25;
  $(1h).OBV().trend == BULLISH;
} = BUY;
```

**示例 2: 多时间框架部分共振**
```javascript
// 至少2个时间框架看涨
MIN(2) {
  $(5m).MA().trend = BULLISH;
  $(15m).MA().trend = BULLISH;
  $(1h).MA().trend = BULLISH;
  $(4h).MA().trend = BULLISH;
} = BUY;
```

**适用场景**:
- 🎯 平衡型策略
- 🎯 多维度弱确认
- 🎯 降低ALL的严格度

---

### 3.2 COUNT - 正好满足

**功能**: 正好满足 N 个条件时触发信号。

**语法**:
```javascript
COUNT(n) {
  condition1;
  condition2;
  ...
} = SIGNAL_TYPE;
```

**参数**:
- `n`: 需要恰好满足的条件数量（整数，> 0）

**特点**:
- ✅ 精确的数量匹配
- ⚠️ 过于严格，使用较少
- ✅ 适合特定场景

**示例**:
```javascript
// 正好2个指标看涨（不多不少）
COUNT(2) {
  $(1h).MACD().trend = BULLISH;
  $(1h).RSI().value > 50;
  $(1h).ADX().value > 25;
} = BUY;
```

**适用场景**:
- 🎯 特殊模式识别
- 🎯 精确条件匹配
- ⚠️ 使用较少，建议优先使用MIN或VOTE

### 3.3 MAX - 最多满足

**功能**: 最多满足 N 个条件时触发信号。

**语法**:
```javascript
MAX(n) {
  condition1;
  condition2;
  ...
} = SIGNAL_TYPE;
```

**参数**:
- `n`: 最多允许满足的条件数量（整数，> 0）

- ✅ 适合风险控制

**示例**:

```javascript
// 最多1个指标超买（避免过热）

```

**适用场景**:
- 🎯 风险控制
- 🎯 避免市场过热
- 🎯 反向确认

### 3.4 VOTE - 投票机制 ⭐ NEW

**功能**: 支持两种模式的投票机制，适合民主决策。

**语法**:
```javascript
// 模式1: 整数模式（至少N个）
VOTE(n) {
  condition1;
  condition2;
  ...
} = SIGNAL_TYPE;

// 模式2: 百分比模式（至少x%）
VOTE(0.x) {
  condition1;
  condition2;
  ...
} = SIGNAL_TYPE;
```

**参数**:
- `n > 1`: 整数模式，至少满足 N 个条件
- `0 < n < 1`: 百分比模式，至少满足 x% 的条件

**特点**:
- ✅ **灵活性最强** - 支持数量和百分比两种模式
- ✅ **语义清晰** - "投票"概念直观易懂
- ✅ **扩展性强** - 动态添加条件无需修改阈值（百分比模式）
- ✅ **推荐使用** - 替代 MIN 的更好选择

**示例 1: 整数模式（固定数量）**
```javascript
// 至少3个指标看涨
VOTE(3) {
  $(1h).MACD().trend = BULLISH;
  $(1h).RSI().value > 50;
  $(1h).ADX().value > 25;
  $(1h).OBV().trend == BULLISH;
  $(1h).MA().golden_cross = true;
} = BUY;
```

**示例 2: 百分比模式（动态比例）⭐ 推荐**
```javascript
// 至少60%的指标看涨
VOTE(0.6) {
  $(1h).MACD().trend = BULLISH;
  $(1h).RSI().value > 50;
  $(1h).ADX().value > 25;
  $(1h).OBV().trend == BULLISH;
  $(1h).MA().golden_cross = true;
} = BUY;

// 好处：未来添加新条件无需修改0.6这个阈值！
```

**示例 3: 多时间框架投票**
```javascript
// 大多数时间框架看涨（60%）
VOTE(0.6) {
  $(1m).RSI().value > 50;
  $(5m).RSI().value > 50;
  $(15m).RSI().value > 50;
  $(30m).RSI().value > 50;
  $(1h).RSI().value > 50;
} = BUY;
```

**示例 4: 综合策略投票**
```javascript
// 趋势、动量、成交量、波动率综合投票
VOTE(0.7) {
  // 趋势类
  $(1h).MACD().trend = BULLISH;
  $(1h).MA().golden_cross = true;
  $(1h).ADX().value > 25;
  
  // 动量类
  $(1h).RSI().value BETWEEN(40, 60);
  $(1h).STOCHRSI().k > $(1h).STOCHRSI().d;
  
  // 成交量类
  $(1h).OBV().trend == BULLISH;
  $(1h).MFI().value > 50;
  
  // 波动率类
  $(1h).BOLL().position = MIDDLE;
  $(1h).ATR().trend == BULLISH;
} = BUY;
```

**VOTE vs MIN 对比**:

| 维度 | VOTE | MIN |
|------|------|-----|
| **语义** | 投票机制（民主） | 至少满足（技术） |
| **灵活性** | 支持百分比 | 仅支持整数 |
| **扩展性** | 百分比模式下添加条件无需修改阈值 | 添加条件需要重新评估阈值 |
| **推荐度** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |

**适用场景**:
- 🎯 **多指标综合决策** - 推荐使用百分比模式
- 🎯 **多时间框架共振** - 灵活的比例控制
- 🎯 **策略模块化** - 各模块独立投票
- 🎯 **动态策略** - 容易添加/删除条件

**最佳实践**:
```javascript
// ⭐ 推荐：使用百分比模式
VOTE(0.6) { ... }  // 至少60%同意

// ✅ 可选：使用整数模式（条件数量固定时）
VOTE(3) { ... }    // 至少3个同意

// ⚠️ 不推荐：使用MIN（语义不如VOTE清晰）
MIN(3) { ... }     // 虽然功能相同，但"投票"更直观
```

## 4. 加权信号函数

### 4.1 WEIGHTED - 加权评分

**功能**: 为不同条件分配权重，根据总分触发信号。

**语法**:
```javascript
WEIGHTED(threshold) {
  WEIGHT(condition1) = weight1;
  WEIGHT(condition2) = weight2;
  ...
} = SIGNAL_TYPE;
```

**参数**:
- `threshold`: 触发阈值（0.0 ~ 1.0）
- `weight`: 每个条件的权重（0.0 ~ 1.0）

**特点**:
- ✅ **精细控制** - 为重要条件分配更高权重
- ✅ **量化评分** - 提供信号强度指标
- ✅ **专业策略** - 适合复杂的量化策略
- ⚠️ **复杂度高** - 需要合理设计权重

**示例 1: 基础加权评分**
```javascript
// 买入信号：加权评分 >= 0.6
WEIGHTED(0.6) {
  WEIGHT($(5m).MACD().crossover_type = "GOLDEN_CROSS") = 0.4;  // 最重要
  WEIGHT($(5m).RSI().value < 50) = 0.2;                       // 次要
  WEIGHT($(1h).MACD().trend = "BULLISH") = 0.3;               // 重要
  WEIGHT($(5m).EMA().golden_cross = true) = 0.3;              // 重要
} = BUY;
```

**示例 2: 多维度加权**
```javascript
// 趋势权重最高，其次动量，最后成交量
WEIGHTED(0.7) {
  // 趋势类（50%权重）
  WEIGHT($(1h).MACD().trend = "BULLISH") = 0.3;
  WEIGHT($(1h).MA().golden_cross = true) = 0.2;
  
  // 动量类（30%权重）
  WEIGHT($(1h).RSI().value > 50) = 0.15;
  WEIGHT($(1h).STOCHRSI().k > $(1h).STOCHRSI().d) = 0.15;
  
  // 成交量类（20%权重）
  WEIGHT($(1h).OBV().trend == BULLISH) = 0.1;
  WEIGHT($(1h).MFI().value > 50) = 0.1;
} = BUY;
```

**示例 3: 多条件共享权重（AND逻辑）**
```javascript
WEIGHTED(0.6) {
  // 多个条件全部满足才得0.4
  WEIGHT(
    $(5m).MACD().crossover_type = GOLDEN_CROSS;
    $(5m).EMA().golden_cross = true;
    $(5m).RSI().value < 30;
  ) = 0.4;
  
  // 单个条件
  WEIGHT($(1h).MACD().trend = BULLISH) = 0.3;
  WEIGHT($(1h).ADX().value > 25) = 0.3;
} = BUY;
```

**权重设计原则**:
1. **总权重可超过1.0** - 满分越高，触发难度越高
2. **核心条件高权重** - 最重要的条件分配 30%-50% 权重
3. **辅助条件低权重** - 次要条件分配 10%-20% 权重
4. **权重平衡** - 避免单一条件主导决策

**适用场景**:
- 🎯 **复杂量化策略**
- 🎯 **多因子模型**
- 🎯 **信号强度评估**
- 🎯 **条件重要性差异大**

## 5. 信号函数对比

### 5.1 功能对比

| 信号函数 | 触发条件 | 严格度 | 灵活性 | 推荐场景 |
|----------|----------|--------|--------|----------|
| **ALL** | 全部满足 | ⭐⭐⭐⭐⭐ | ⭐ | 高确定性策略 |
| **ANY** | 任一满足 | ⭐ | ⭐⭐⭐⭐⭐ | 多机会捕捉 |
| **NONE** | 全部不满足 | ⭐⭐⭐⭐⭐ | ⭐ | 风险过滤 |
| **MIN** | 至少N个 | ⭐⭐⭐ | ⭐⭐⭐ | 平衡型策略 |
| **COUNT** | 正好N个 | ⭐⭐⭐⭐⭐ | ⭐ | 特殊模式（少用） |
| **MAX** | 最多N个 | ⭐ | ⭐⭐⭐ | 风险控制 |
| **VOTE** ⭐ | 投票机制 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 多维度决策（推荐） |
| **WEIGHTED** | 加权评分 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 复杂量化策略 |

### 5.2 选择建议

**简单策略**:
```
ALL  → 严格确认
ANY  → 宽松触发
NONE → 风险过滤
```

**中等策略**:
```
VOTE(0.6) → 民主投票（推荐）
MIN(2) → 部分确认
```

**复杂策略**:
```
WEIGHTED(0.7) → 专业评分
VOTE(0.7) + WEIGHTED(0.6) → 分层验证
```

## 6. 最佳实践

### 6.1 信号函数设计原则

#### 原则1: 语义清晰
```javascript
// ✅ 好：语义清晰
VOTE(0.6) {
  $(1h).MACD().trend = BULLISH;
  $(1h).RSI().value > 50;
  $(1h).OBV().trend == BULLISH;
} = BUY;

// ❌ 差：逻辑模糊
ANY {
  NOT($(1h).MACD().trend = BEARISH);
  NOT($(1h).RSI().value <= 50);
} = BUY;
```

#### 原则2: 避免过度复杂
```javascript
// ✅ 好：分层简洁
VOTE(0.6) {
  $(1h).MACD().trend = BULLISH;
  $(1h).RSI().value > 50;
  $(1h).ADX().value > 25;
} = BUY;

// ❌ 差：单层过于复杂
WEIGHTED(0.7) {
  WEIGHT($(5m).MACD().trend = "BULLISH", $(15m).MACD().trend = "BULLISH") = 0.2;
  WEIGHT($(5m).RSI().value > 50, $(15m).RSI().value > 50) = 0.2;
  WEIGHT($(5m).ADX().value > 25, $(15m).ADX().value > 25) = 0.2;
  // ... 太多条件
} = BUY;
```

#### 原则3: 合理使用嵌套
```javascript
// ✅ 好：2层嵌套
VOTE(0.6) {
  $(1h).MACD().trend == BULLISH;
  $(1h).RSI().value > 50;
  $(1h).ADX().value > 25;
} = BUY;

// ⚠️ 警告：过度嵌套
ALL {
  VOTE(2) {
    MIN(1) {
      $(1h).RSI().value > 50
    },
    // ... 过于复杂
  }
} = BUY;
```

### 6.2 性能优化建议

#### 建议1: 将快速条件放前面
```javascript
// ✅ 好：简单条件优先
VOTE(2) {
  $(1h).RSI().value > 50;           // 快
  $(1h).MACD().trend = BULLISH;   // 较快
  CONSECUTIVE(1h).close(3).INCREASING()  // 慢
} = BUY;
```

#### 建议2: 避免重复计算
```javascript
// ❌ 差：重复计算$(1h).MACD
VOTE(2) {
  $(1h).MACD().dif > 0;
  $(1h).MACD().dea > 0;
  $(1h).MACD().histogram > 0;
} = BUY;

// ✅ 好：利用已有字段
VOTE(2) {
  $(1h).MACD().trend = BULLISH;  // 内部已综合判断
  $(1h).RSI().value > 50
} = BUY;
```

### 6.3 可维护性建议

#### 建议1: 添加注释
```javascript
// 多维度趋势确认策略
VOTE(0.6) {
  // 趋势指标
  $(1h).MACD().trend = BULLISH;
  $(1h).MA().golden_cross = true;
  
  // 动量指标
  $(1h).RSI().value > 50;
  $(1h).ADX().value > 25;
  
  // 成交量确认
  $(1h).OBV().trend == BULLISH
} = BUY;
```

#### 建议2: 参数化配置
```javascript
// 定义阈值参数
DEFINE CONST VOTE_THRESHOLD = 0.6;
DEFINE CONST RSI_LEVEL = 50;

VOTE(VOTE_THRESHOLD) {
  $(1h).RSI().value > RSI_LEVEL;
  $(1h).MACD().trend = BULLISH;
} = BUY;
```

## 7. 常见问题

### Q1: VOTE 和 MIN 有什么区别？

**A**: 功能相同，但语义不同。
- **VOTE**: 投票机制，支持百分比模式，语义更清晰
- **MIN**: 至少满足，仅支持整数模式，技术性更强

**推荐**: 优先使用 **VOTE**，特别是百分比模式（`VOTE(0.6)`）

### Q2: 如何选择 VOTE 的阈值？

**A**: 根据策略风格选择。
- **保守型**: `VOTE(0.8)` 或 `VOTE(0.9)` - 80-90%同意
- **平衡型**: `VOTE(0.6)` 或 `VOTE(0.7)` - 60-70%同意
- **积极型**: `VOTE(0.5)` - 超过半数同意

### Q3: WEIGHTED 的权重如何设计？

**A**: 遵循以下原则。
1. **核心条件30-50%权重** - 最重要的条件
2. **辅助条件10-20%权重** - 次要条件
3. **总权重可超过1.0** - 提高触发难度
4. **避免单一主导** - 不要让一个条件占比例过高

### Q4: 可以嵌套信号函数吗？

**A**: 不推荐。信号函数应该是顶层构造，用于生成最终信号。如果需要复杂逻辑，建议：
- 使用自定义函数封装复杂条件
- 使用变量存储中间结果
- 分层设计策略

### Q5: 如何调试信号函数？

**A**: 使用以下方法。
1. **简化条件** - 逐个测试条件
2. **使用变量** - 存储中间判断结果
3. **输出日志** - 查看每个条件的满足情况
4. **回测验证** - 使用历史数据测试

### Q6: 信号函数的返回值是什么？

**A**: 信号函数内部返回满意度评分（0.0 ~ 1.0），但最终会转换为布尔值：
- **满足**: 评分 > 0.5 → `true` → 触发对应信号
- **不满足**: 评分 ≤ 0.5 → `false` → 不触发信号

### Q7: 可以在一个策略中使用多个信号函数吗？

**A**: 可以，但需要通过条件语句组织。
```javascript
// 方式1: 使用自定义函数组织
calcSignal(condition1: Boolean): Signal {
  if (condition1) {
    return BUY;
  } else {
    return SELL;
  }
}

// 方式2: 分层定义（使用全局变量）
@trend_ok: Boolean = VOTE(0.6) { ... } = BUY;
@momentum_ok: Boolean = ALL { ... } = BUY;

ALL{
  @trend_ok;
  @momentum_ok;
} = BUY;
```

### Q8: 止盈止损是必须的吗？

**A**: 不是必须的。如果未指定止盈止损，系统会使用默认值`0.0`，Python 层会重新计算。但**强烈建议**在策略中明确指定止盈止损，以实现更好的风险管理。

### Q9: 止盈止损表达式计算失败怎么办？

**A**: 如果止盈止损表达式计算失败（例如除零、函数调用失败等），系统会使用默认值`0.0`，Python 层会检测到并重新计算。建议在表达式中避免可能导致错误的操作。

### Q10: 可以使用变量存储止盈止损价格吗？

**A**: 可以。止盈止损表达式支持变量引用：
```javascript
@current_price: Double = KLINE(5m).close();
@atr: Double = $(5m).ATR().value;
@tp_price: Double = @current_price + @atr * 2.0;
@sl_price: Double = @current_price - @atr * 1.5;

ALL{...} = BUY(@tp_price, @sl_price);
```

### Q11: 如何计算合理的止盈止损距离？

**A**: 推荐使用 ATR（平均真实波幅）作为基准：
```javascript
@atr: Double = $(5m).ATR().value;

// 保守策略：止盈2倍ATR，止损1.5倍ATR
ALL{...} = BUY(
  KLINE(5m).close() + @atr * 2.0,
  KLINE(5m).close() - @atr * 1.5
);

// 激进策略：止盈3倍ATR，止损1倍ATR
ALL{...} = BUY(
  KLINE(5m).close() + @atr * 3.0,
  KLINE(5m).close() - @atr * 1.0
);
```
