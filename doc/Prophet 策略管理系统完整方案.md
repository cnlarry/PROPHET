## 核心概念

### 1. 策略 (Strategy)
**策略是一个"产品"**，拥有多个版本，可以被多个用户使用。

- **策略所有者**：创建策略的用户（owner_id）
- **策略当前版本**：策略所有者推荐的版本（current_*_version）
- **策略启用状态**：enabled 字段
  - `enabled=false`：草稿状态（只有所有者可见）
  - `enabled=true`：已激活（可被其他用户订阅使用）

### 2. 策略版本 (Strategy DSL Version)
**版本是策略的"快照"**，包含DSL代码和参数，不可修改。

- **版本号**：采用语义化版本 `vX.Y.Z`
  - Major：破坏性更改
  - Minor：向下兼容的功能增强
  - Patch：向下兼容的bug修复
  
- **版本状态**：
  - `draft`：草稿（编辑中）
  - `active`：激活可用
  - `deprecated`：已废弃但仍可用（推荐升级）
  - `archived`：已归档不可用（强制升级）

### 3. 策略实例 (Strategy Instance)
**实例是用户对策略的"订阅"**，绑定特定版本，可以运行。

- **版本锁定**：用户选择并锁定一个版本运行
- **运行环境**：backtest（回测）、paper（模拟盘）、live（实盘）
- **运行状态**：running、stopped、paused

## 三表关系

```
┌─────────────────────────────────────────────────────────────────┐
│                         strategies                              │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ id: "stg_abc123"                                         │   │
│  │ name: "趋势追踪策略"                                      │   │
│  │ owner_id: "user_001"                                     │   │
│  │ current_version: v2.1.0  ← 所有者推荐版本                │   │
│  │ enabled: true            ← 是否公开可用                  │   │
│  │ public: true             ← 是否允许其他人订阅             │   │
│  └──────────────────────────────────────────────────────────┘   │
└────────────┬────────────────────────────────┬───────────────────┘
             │                                │
             │ 1 对 N                         │ 1 对 N
             │                                │
┌────────────▼────────────────┐   ┌───────────▼──────────────────┐
│ strategy_dsl_versions       │   │ strategy_instances           │
├─────────────────────────────┤   ├──────────────────────────────┤
│ v1.0.0 - draft   (初始版本)│   │ 用户A订阅 - 锁定v1.0.0       │
│ v1.0.1 - active  (修复bug) │   │   environment: backtest      │
│ v1.1.0 - active  (新功能)  │   │   status: running            │
│ v2.0.0 - active  (重构)    │   ├──────────────────────────────┤
│ v2.1.0 - active  (当前版本)│   │ 用户B订阅 - 锁定v2.0.0       │
│                             │   │   environment: live          │
│ 每个版本都是独立快照         │   │   status: running            │
│ 包含完整的DSL和参数          │   │   has_newer_version: true   │
└─────────────────────────────┘   └──────────────────────────────┘
```

### 关键设计理念

1. **策略表只存元信息**：不存DSL代码，只指向当前推荐版本
2. **版本表存快照**：每个版本是完整的、不可变的代码快照
3. **实例表存用户状态**：用户锁定版本、自定义参数、运行状态

## 策略状态与生命周期

### 策略主表的 `enabled` 字段

```
enabled = false (草稿状态)
├─ 只有所有者可见
├─ 可以编辑名称、symbol、remarks
├─ 可以创建新版本
└─ 不能被其他用户订阅

enabled = true (已激活)
├─ 所有人可见（如果 public=true）
├─ 不能编辑名称、symbol、remarks（避免混淆）
├─ 可以创建新版本
└─ 其他用户可以订阅使用
```

### 版本的状态流转

```
draft → active → deprecated → archived
  ↓       ↓         ↓           ↓
编辑中   可正常    建议升级    强制升级
        使用      但仍可用    必须升级
```

**状态说明：**

1. **draft（草稿）**
   - 新创建的版本
   - 可以修改DSL和参数（实际上是删除重建）
   - 只有所有者可见
   - 不能被用户订阅

2. **active（激活）**
   - 可正常使用的版本
   - 用户可以订阅此版本
   - 不可修改（immutable）

3. **deprecated（已废弃）**
   - 建议用户升级的旧版本
   - 仍然可以运行
   - 前端显示"有新版本可用"提示
   - `has_newer_version=true`

4. **archived（已归档）**
   - 已停用的版本（通常因为严重bug或安全问题）
   - 不能继续运行
   - 用户必须升级到新版本
   - `force_upgrade_required=true`

## 核心业务逻辑

### 1. 创建策略

```
用户操作：
1. 点击"新建策略"按钮
2. 在编辑器中编写DSL代码
3. 点击"保存"，填写策略名称、Symbol、备注

后端逻辑：
1. 创建 strategies 记录
   - id: 生成唯一ID
   - owner_id: 当前用户ID
   - enabled: false (草稿状态)
   - current_version: 1.0.0

2. 创建 strategy_dsl_versions 记录
   - version: v1.0.0
   - status: draft
   - dsl: 用户编写的代码
   - parameters: 默认参数（空JSON）

结果：
- 策略出现在用户的"草稿"列表中
```

### 2. 编辑策略信息

```
前提条件：
- 策略必须是草稿状态 (enabled=false)
- 用户必须是策略所有者

可编辑内容：
- 策略名称 (name)
- 交易对 (symbol)
- 备注 (remarks)

操作方式：
1. 右键策略卡片
2. 选择"编辑信息"
3. 修改后保存

后端逻辑：
- UPDATE strategies 表的对应字段
- 不影响版本数据
```

### 3. 修改策略代码（创建新版本）

```
用户操作：
1. 双击策略卡片，打开编辑器
2. 修改DSL代码
3. 点击"保存"

后端逻辑：
1. 检查是否是策略所有者
2. 获取当前最大版本号
3. 根据变更类型计算新版本号：
   - 用户选择：major/minor/patch
   - 自动递增对应位
   
4. 创建新的 strategy_dsl_versions 记录
   - 新版本号
   - status: active (如果策略已激活) 或 draft (如果策略是草稿)
   - dsl: 新的代码
   
5. 更新 strategies 表的 current_*_version
6. （可选）将旧版本标记为 deprecated

结果：
- 策略有了新版本
- 现有用户实例不受影响（版本锁定）
```

### 4. 激活策略

```
前提条件：
- 策略是草稿状态 (enabled=false)
- 策略至少有一个版本
- 用户是策略所有者

用户操作：
1. 右键策略卡片
2. 选择"激活策略"
3. 选择激活方式：
   - 私有激活 (enabled=true, public=false)
   - 激活并共享 (enabled=true, public=true)

后端逻辑：
1. 验证策略有有效版本
2. 将策略的 enabled 设置为 true
3. 将当前版本的 status 设置为 active（如果还是draft）
4. 设置 public 字段

结果：
- 策略状态从"草稿"变为"激活"
- 如果选择"私有激活"：只有所有者可见和使用
- 如果选择"激活并共享"：策略出现在"策略市场"，其他用户可订阅
```

**重要说明：共享机制**
- ⚠️ 只有 enabled=true 且 public=true 的策略才能被其他用户订阅
- 所有者可以先私有激活，测试无误后再共享
- 共享后所有者仍可创建新版本、修改版本状态等
- 详见：`Prophet 策略共享机制与权限控制.md`

### 5. 共享策略（公开给其他用户）

```
前提条件：
- 策略已激活但未共享 (enabled=true, public=false)
- 用户是策略所有者

用户操作：
1. 右键策略卡片
2. 选择"共享策略"
3. 确认对话框提示：
   - "共享后其他用户可以在策略市场看到并订阅"
   - "您仍然拥有完全控制权"
4. 点击确认

后端逻辑：
1. 验证策略已激活
2. 将策略的 public 设置为 true

结果：
- 策略出现在"策略市场"
- 其他用户可以订阅此策略
- 所有者仍可创建新版本、管理版本状态
```

### 6. 取消共享

```
前提条件：
- 策略已共享 (enabled=true, public=true)
- 用户是策略所有者

用户操作：
1. 右键策略卡片
2. 选择"取消共享"
3. 警告对话框显示：
   - 当前订阅者数量
   - 取消共享的影响
4. 确认后执行

后端逻辑：
1. 将策略的 public 设置为 false
2. 不影响现有订阅者的实例

结果：
- 策略从"策略市场"移除
- 新用户无法订阅
- 现有订阅者仍可使用当前锁定的版本
- 现有订阅者无法看到新版本更新
```

### 7. 废弃策略

```
前提条件：
- 策略已激活 (enabled=true)
- 用户是策略所有者

用户操作：
1. 右键策略卡片
2. 选择"废弃"

后端逻辑：
1. 将策略的 enabled 设置为 false
2. 将当前版本的 status 设置为 deprecated
3. 设置 deprecation_reason（可选）

结果：
- 策略不再出现在"策略市场"
- 现有用户实例继续运行
- 用户收到"策略已废弃"提示
```

### 8. 归档策略（强制下线）

```
前提条件：
- 策略已激活或已废弃
- 用户是策略所有者
- 通常因为严重bug或安全问题

用户操作：
1. 右键策略卡片
2. 选择"归档"
3. 填写归档原因
4. 警告对话框显示影响的订阅者数量
5. 确认后执行

后端逻辑：
1. 将策略的 enabled 设置为 false
2. 将所有版本的 status 设置为 archived
3. 将所有用户实例的 force_upgrade_required 设置为 true
4. 停止所有正在运行的实例

结果：
- 策略完全下线
- 所有用户实例停止运行
- 用户必须选择新策略或新版本
```

### 9. 删除策略

```
前提条件：
- 策略是草稿状态 (enabled=false)
- 没有用户订阅（strategy_instances 表中没有记录）
- 用户是策略所有者

用户操作：
1. 右键策略卡片
2. 选择"删除"
3. 确认删除

后端逻辑：
1. 检查是否有用户实例
2. CASCADE 删除所有版本记录
3. 删除 strategies 记录

结果：
- 策略及其所有版本被永久删除
```

**重要：删除限制**
- ❌ 已激活的策略不能删除
- ❌ 有订阅者的策略不能删除
- ✅ 只能删除草稿状态且无订阅者的策略
- 💡 如需停用已共享的策略，请使用"废弃"或"归档"

### 10. 订阅策略（用户订阅其他人的策略）

```
前提条件：
- 策略已激活 (enabled=true)
- 策略公开 (public=true)
- 用户尚未订阅此策略

用户操作：
1. 在"策略市场"浏览策略
2. 点击策略查看详情
3. 选择要使用的版本
4. 点击"订阅"

后端逻辑：
1. 创建 strategy_instances 记录
   - strategy_id: 策略ID
   - user_id: 当前用户ID
   - locked_*_version: 用户选择的版本
   - status: stopped
   - environment: 用户选择（backtest/paper/live）

结果：
- 策略出现在用户的"我的策略"列表
- 用户可以配置参数并运行
```

### 11. 升级策略版本（用户主动升级）

```
前提条件：
- 用户已订阅策略
- 有新版本可用

用户操作：
1. 在"我的策略"中看到"有新版本"提示
2. 点击"升级"
3. 选择新版本
4. 确认升级

后端逻辑：
1. 停止当前运行的实例
2. 更新 strategy_instances 的 locked_*_version
3. 清除 has_newer_version 标记

结果：
- 用户实例使用新版本
- 可以重新启动运行
```

## 用户角色与权限

### 角色定义

1. **策略所有者 (Strategy Owner)**
   - 创建策略的用户
   - 拥有完全控制权

2. **策略订阅者 (Strategy Subscriber)**
   - 使用他人公开策略的用户
   - 只能运行，不能修改

3. **普通用户 (Regular User)**
   - 可以创建自己的策略
   - 可以订阅他人的公开策略

### 权限矩阵

| 操作 | 所有者（草稿） | 所有者（已激活） | 订阅者 |
|------|---------------|-----------------|--------|
| 查看策略 | ✅ | ✅ | ✅ |
| 编辑名称/Symbol/备注 | ✅ | ❌ | ❌ |
| 修改DSL代码（创建新版本） | ✅ | ✅ | ❌ |
| 激活策略 | ✅ | ❌ | ❌ |
| 废弃策略 | ❌ | ✅ | ❌ |
| 归档策略 | ❌ | ✅ | ❌ |
| 删除策略 | ✅（无订阅者） | ❌ | ❌ |
| 订阅策略 | ❌ | ❌ | ✅ |
| 运行策略 | ✅ | ✅ | ✅ |
| 选择版本 | ✅ | ✅ | ✅ |

## 完整业务流程

### 流程1：策略从创建到发布

```
1. [草稿阶段]
   用户A创建策略 "趋势追踪"
   ├─ 编写DSL代码
   ├─ 保存为 v1.0.0 (draft)
   ├─ 在草稿中测试、修改
   └─ 可以重命名、修改信息

2. [测试阶段]
   用户A激活策略（私有）
   ├─ enabled=true, public=false
   ├─ v1.0.0 变为 active
   ├─ 创建自己的实例进行回测
   └─ 发现bug，修复并创建 v1.0.1

3. [发布阶段]
   用户A公开策略
   ├─ 设置 public=true
   ├─ 策略出现在"策略市场"
   └─ 其他用户可以订阅

4. [维护阶段]
   用户A持续改进
   ├─ 发布 v1.1.0 (新功能)
   ├─ 发布 v2.0.0 (重构)
   ├─ 将 v1.x 标记为 deprecated
   └─ current_version 指向 v2.0.0
```

### 流程2：用户订阅和使用策略

```
1. [发现阶段]
   用户B浏览"策略市场"
   ├─ 看到用户A的"趋势追踪"策略
   ├─ 查看策略详情、历史收益
   └─ 选择订阅

2. [订阅阶段]
   用户B订阅策略
   ├─ 选择版本：v2.0.0 (推荐) 或 v1.1.0 (稳定)
   ├─ 创建 strategy_instance
   └─ 锁定版本 v2.0.0

3. [配置阶段]
   用户B配置实例
   ├─ 选择运行环境：backtest
   ├─ （可选）覆盖参数
   └─ 启动回测

4. [升级决策]
   用户A发布 v2.1.0
   ├─ 用户B收到"有新版本"提示
   ├─ 查看版本更新说明
   ├─ 决定继续使用 v2.0.0 ✅
   └─ 或者升级到 v2.1.0 ✅
```

### 流程3：强制升级场景

```
1. [发现严重Bug]
   用户A发现 v2.0.0 有严重安全漏洞
   
2. [发布修复版本]
   用户A发布 v2.0.1
   ├─ 修复安全漏洞
   └─ change_type: patch

3. [归档旧版本]
   用户A将 v2.0.0 归档
   ├─ status: archived
   ├─ force_upgrade: true
   └─ deprecation_reason: "严重安全漏洞"

4. [强制升级]
   系统自动处理
   ├─ 停止所有使用 v2.0.0 的实例
   ├─ 设置 force_upgrade_required=true
   └─ 发送通知给用户

5. [用户响应]
   用户B必须升级
   ├─ 选择新版本 v2.0.1 或 v2.1.0
   ├─ 更新实例的 locked_version
   └─ 重新启动
```

## 总结

这是一个完整的策略管理系统设计方案，核心思想是：

1. **策略是产品**：有版本、有生命周期、可以共享
2. **版本是快照**：不可变、可追溯、支持多版本并存
3. **实例是订阅**：用户锁定版本、独立配置、独立运行

这种设计既支持个人使用（创建-编辑-运行），也支持协作共享（发布-订阅-升级），还能处理版本管理的复杂场景（废弃-归档-强制升级）。
